# HEP Project Template

A reproducible, agent-ready template for a high-energy theory research project:
a **JHEP paper** together with the **Mathematica** (analytic) and **Python** (numerical)
calculations behind it, wired so that every equation, number and figure in the PDF is
generated by a script. It ships with [Claude Code](https://claude.com/claude-code)
instructions, rules and skills.

## Quick start

On GitHub, open this repository and click **Use this template → Create a new repository**,
then:

```bash
git clone git@github.com:<you>/<my-project>.git
cd <my-project>
make setup          # uv env, notebook git filter, tool check
make all            # calculations -> values -> paper/main.pdf
claude              # then run /init-project
```

(With the GitHub CLI the first step is
`gh repo create <my-project> --private --template <you>/Project-Template --clone`.)

Requirements: TeX Live (`latexmk`, `pdflatex`), [uv](https://docs.astral.sh/uv/),
Mathematica (optional for building the paper; generated outputs are committed).
The paper is pdflatex-only (arXiv); in VS Code, LaTeX Workshop picks this up from the shared
`.vscode/settings.json` (it runs `latexmk` with `paper/latexmkrc`, exactly like `make paper`).

To let Claude Code run Mathematica, every collaborator installs the official
[Wolfram MCP server](https://resources.wolframcloud.com/PacletRepository/resources/Wolfram/MCPServer/tutorial/QuickStartforAICodingApplications.html)
**once, globally** (the project ships no `.mcp.json`, since it would contain machine-specific
paths). In a Wolfram Language session (kernel or notebook) run

```wolfram
PacletInstall["Wolfram/MCPServer"];
Needs["Wolfram`AgentTools`"];
InstallMCPServer["ClaudeCode", "WolframLanguage"]
```

then restart Claude Code and check that `claude mcp get Wolfram` reports `Connected`. The server
must be registered under the name `Wolfram`: the permission rules in `.claude/settings.json`
refer to `mcp__Wolfram__*`.

Mathematica notebooks (`*.nb`) are committed **without outputs**: `make setup` registers a git
filter (`tools/nbstrip.py`) that, when a notebook is staged, removes output/print/message cells,
the front-end cache and volatile metadata (cell timestamps, UUIDs, `In[n]` labels, window
geometry). Your working copy keeps its outputs; collaborators re-evaluate after pulling.
Run `make setup` in every clone (the filter lives in local git config); notebooks committed
before that are cleaned with `git add --renormalize '*.nb'`, and `make test` fails if a committed
notebook is not stripped.

## How it fits together

```
calc/mathematica/scripts/01_*.wl ──ExportAnalytic──▶ results/analytic/*.json ──▶ paper/generated/eq_*.tex
                                 ──ExportValues───▶ results/*.json ─┐
calc/python/scripts/02_*.py ◀── hepcalc.bridge (sympy) ──┘          │
                            ──export_values──▶ results/*.json ──────┤
                            ──plotting.save──▶ paper/figures/*.pdf  │
                                    make values ◀───────────────────┘
                                          ▼
                     paper/generated/values.tex  (\valCRatio, ...)  ──▶  make paper
```

- **Numbers** in the paper are macros: a script exports `"CRatio" -> 0.5` and the
  paper writes `\valCRatio`. Change the calculation, run `make all`, the paper updates.
- **Equations** from Mathematica are exported as TeX and `\input` in the paper.
- **Analytic → numeric**: Python loads Mathematica results with `hepcalc.bridge.lambdify`.
- Scripts are numbered globally (`01_…wl`, `02_…py`) and run in order by `make calc`.

The included example is the paper *Supergravity flows, wormholes and their pseudo-Hermitian
holographic duals* ([arXiv:2605.16168](https://arxiv.org/abs/2605.16168)), restructured so
that its key results are regenerated and checked by the pipeline:

| Script | Reproduces |
|---|---|
| `01_wormhole_backgrounds.wl` | BPS wormholes (ex. 1, 2, 5) solve the full Einstein + ghost-scalar equations; asymptotics; V(η); Δη vs. the bound of sec. 5; analytic mutual-information slopes |
| `02_ghost_fluctuations.wl` | the Z_η fluctuation equation of app. C, derived from the general gauge-invariant equation and checked against the paper |
| `03_ghost_spectrum.py` | table 1, example 1: Chebyshev spectral method, convergence-checked |
| `04_mutual_information.py` | fig. 2 and the large-width fits, slopes checked against the analytic result |
| `05_ghost_spectrum_ex2.py` | table 1, example 2, following the original notebook: closed-form solution, regularity at the throat, vanishing source |

The schematic figure lives in `paper/images/` (hand-made art is the only exception to
"every figure is generated"). `/init-project` removes the example.

## Layout

```
paper/            JHEP LaTeX (main.tex, sections/, macros.tex, references.bib)
  generated/      ← written by calc scripts (do not edit)
  figures/        ← written by calc scripts
  images/         hand-made artwork (diagrams); the only non-generated figures
calc/
  mathematica/    Project.wl (pipeline infrastructure), packages/ (physics packages shared by
                  notebooks and scripts), scripts/NN_*.wl, notebooks/
  python/         hepcalc/ package, scripts/NN_*.py, tests/, notebooks/
  other/          how to add FORM, Julia, C++, MadGraph, ...
results/          numerical results (*.json) and analytic expressions (analytic/*.json)
data/             raw/ (inputs, read-only), processed/ (generated, git-ignored)
notes/            conventions.md, log.md (research log), derivations/
literature/       one note per paper (INSPIRE texkey)
tools/            run-calcs.sh, make-arxiv.sh, nbstrip.py (notebook git filter)
.claude/          rules/ (instructions, mostly path-scoped), skills/, settings.json
CLAUDE.md         project instructions for the agent
```

## Make targets

| Target | |
|---|---|
| `make setup` | `uv sync`, register the notebook git filter, check tools |
| `make calc` / `make calc ONLY=03` / `make calc-py` | run calculations |
| `make values` | rebuild `paper/generated/values.tex` |
| `make paper` / `make watch` | build the PDF |
| `make all` | calc + paper |
| `make test` / `make lint` | pytest, ruff (lint + format check), chktex |
| `make format` | auto-format Python with ruff (VS Code also does it on save) |
| `make arxiv` | flat tarball for arXiv submission in `build/` |

## Working with Claude Code

`CLAUDE.md` describes the project and its non-negotiables (no hand-typed numbers,
every result cross-checked, conventions in `notes/conventions.md`, INSPIRE-only
citations). Rules in `.claude/rules/` load automatically when the agent touches
LaTeX, Mathematica or Python files; the physics rules (`physics.md`) are always loaded. Mathematica is driven through the official Wolfram MCP
server (installed globally, see Quick start; `WolframLanguageEvaluator`, see `CLAUDE.md`), not `wolframscript`.

| Skill | What it does |
|---|---|
| `/init-project` | interview → title, authors, conventions, tools; removes the example |
| `/new-calc <name> [mathematica\|python]` | scaffold a numbered pipeline script with checks and exports |
| `/verify <eq/result>` | adversarial cross-check: limits, symmetries, numerics, literature |
| `/build-paper` | compile, fix errors, report warnings and TODOs |
| `/sync-results` | rerun the whole pipeline and check paper ↔ results consistency |
| `/add-reference <arXiv/DOI/query>` | BibTeX from INSPIRE + optional literature note |
| `/referee` | JHEP-style referee report on the draft |
| `/log` | append the session to `notes/log.md` |

A typical loop: `/new-calc` → implement with the agent → `/verify` → use `\val…` in
the paper → `/build-paper` → `/log`. Before sending a draft: `/sync-results`, `/referee`.

## Collaboration

Generated outputs are committed, so coauthors (and Overleaf via GitHub sync) can build
the paper without Mathematica. CI (`.github/workflows/ci.yml`) runs the Python tests and
calculations and builds the PDF on every push.
